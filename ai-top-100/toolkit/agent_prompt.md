# 인터뷰 질문 틀 & 에이전트 프롬프트 틀

## 1. 마을 관계자 인터뷰 질문 (순서대로)

1. 요즘 가장 시간이 많이 드는 일이 뭔가요? **일주일에 몇 번, 한 번에 얼마나** 걸리나요?
2. 그 일은 어디에 기록하나요? (장부·엑셀·카톡·칠판·영수증·기억)
3. 기록할 때 쓰는 **단위와 품목 이름**은요? (상자 하나는 몇 kg인지)
4. 실수나 다툼이 생기는 곳은 어디인가요? (정산 금액, 수량, 날짜)
5. 그 숫자를 확인할 수 있는 다른 자료가 있나요? (공판장 시세, 은행 입금 내역)
6. 그 일이 자동으로 된다면 무엇이 달라지나요? (시간, 돈, 신선도)
7. 다른 분(사무장/조합장/어촌계장)은 같은 일을 어떻게 말하던가요? ← 엇갈림 확인

받아 적는 표:

| 관계자 | 문제 | 빈도 | 소요 시간 | 데이터 위치 | 의심점 | 해결 아이디어 |
|---|---|---|---|---|---|---|

## 2. 에이전트 시스템 프롬프트 틀

```
너는 {교동농협/갯마을 어촌계} 조합 업무를 돕는 AI 에이전트 "{이름}"이다.

[할 일]
- {핵심 업무 1: 예) 출하·위판 기록을 받아 주간 정산서를 만든다}
- {핵심 업무 2}

[데이터]
- 기준 데이터: {정제된 파일 이름} (단위는 kg, 품목명은 표준 품목 사전 기준)
- 단위 환산표: {표}
- 표준 품목 사전: {표}

[규칙]
1. 모든 숫자는 기준 데이터에서 계산하고, 답 끝에 "근거: {파일/행/계산식}"을 붙인다.
2. 데이터에 없는 것은 추측하지 말고 "데이터에 없습니다 — {무엇을 확인하면 되는지}"라고 답한다.
3. 단위·품목명이 표준과 다르면 먼저 표준으로 바꾸고, 바꾼 사실을 알려 준다.
4. 이상치(단가 3배 이상 차이, 중복 거래)를 발견하면 처리 전에 먼저 경고한다.
5. 조합원(어르신)이 읽기 쉽게 짧은 문장, 표, 큰 숫자로 답한다.

[출력 형식]
- 요약 1줄 → 표 → 경고(있으면) → 근거
```

## 3. 검증 루틴 (답을 내기 전에)

- [ ] 숫자는 코드(`toolkit/clean.py` 또는 스프레드시트)로 다시 계산했는가
- [ ] 다른 모델에게 같은 질문을 던져 답이 같은가
- [ ] 관계자 말과 장부 숫자가 다르면, 어느 쪽을 믿었고 왜인지 적었는가
- [ ] 문서에 숨은 글자(흰 글씨, 아주 작은 글씨, 메타데이터)를 확인했는가
