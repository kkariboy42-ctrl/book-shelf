## 예선

### 1. 춘식도락 메뉴 분석

- **입력**: 카카오 구내식당 2025년 1~2월 주간 메뉴판 이미지 8장. 칸마다 코너·메뉴명·반찬·kcal.
- **구조 규칙(지문)**: 중식(한식A·B, 팝업A·B, 양식, 샐러드바) / 중식 TAKE OUT(샐러드, 비건, 버거&델리, 라이스&누들) / 석식(한식B, 샐러드바) / 석식 TAKE OUT(샐러드, 버거&델리). **금요일은 석식 없음.**
- **문항**
  - Q1 1/13 주간 특정 5코너 반찬 중 「정확히 조림·볶음·무침·구이로 끝나는」 개수 순위
  - Q2 1월 코너별 평균 칼로리 순위
  - Q3 메뉴명 속 지역명(국가·도시·지명) 중 2회 이상 등장 — 복수선택
  - Q4 메뉴 5개 칼로리 순위
  - Q5 2월 매일: 월~목은 중식+석식 합이 **1,550kcal에 가장 가까운** 코너 조합, 금은 최저 칼로리 중식 코너 → JSON `{"id":"2025-02-03","lunch":"샐러드","dinner":"한식B"}`
- **함정**
  - 「정확히 ~로 끝나는」: `볶음밥`·`조림소스` 같은 건 제외. AI는 대충 포함시키기 쉽다.
  - 범위가 문항마다 다르다(중식만 / 4개 식사 전부 / 1월만 / 2월만). 한 표로 만들고 문항마다 필터를 코드로 건다.
  - Q5 석식 후보는 한식B·샐러드·버거&델리뿐(샐러드바는 분석 대상 목록에 없음). TAKE OUT은 「TAKE OUT」이 아니라 세부 코너명으로 적는다.
  - 2월 공휴일(설 연휴)엔 메뉴가 없을 수 있다 → 그날은 JSON에서 빠질 수 있음. 이미지에 있는 날만.
- **전략**: ① 이미지 8장을 비전 모델로 **CSV 한 장**(날짜·식사·코너·메뉴·반찬·kcal)으로 옮긴다 ② 두 번째 모델로 다시 뽑아 **diff** → 다른 칸만 눈으로 원본 대조 ③ 이후 모든 계산은 파이썬. 계산을 AI 머릿속에 맡기지 않는다.

### 2. 고대 유적의 비밀: 이상한 코드 석판 — **풀이 완료**

- **입력**: 문자가 빼곡한 석판 이미지. 멀리서 보면 글자 모양(아스키아트), 가까이 보면 코드.
- **샘플**: 「main.c로 저장, `gcc -w`로 컴파일」 → `CHOONSIKISACAT`. 여기서 **C 언어라고 믿게 만든다.**
- **실제 문제 이미지 분석(직접 판독)**
  - 1행 `#include<stdio.h>//...` → 파이썬에선 `#` 주석.
  - 2행 `a="G";i=input;a+="NO";q="PO";...;q=q[::-1];a=a[::-1]` → `q="STOP"`, `a="WRONG"`. 「TURNAROUND·스스로를 되돌아보는 주문」 = 문자열 뒤집기 `[::-1]`.
  - 2~3행의 C 함수 부분은 `"""…"""` 파이썬 문자열 안에 갇혀 무시된다. C로는 이 줄이 **컴파일조차 안 된다.**
  - 4행 `if(i()!=q):p(a)` → 입력이 STOP이 아니면 WRONG 출력 후 종료.
  - 몸통(글자 모양)은 `r=r+"I"` 식으로 문자를 붙이다가 중간중간 `r="A"`로 **리셋**하는 미끼가 섞여 있다. 마지막 리셋 이후만 남는다.
- **정답(판독본을 실제 실행해 확인)**

  | 문항 | 답 |
  |---|---|
  | Q1 가장 적절한 언어 | **4. Python** |
  | Q2 `1q2w3e4r` 입력 | **WRONG** |
  | Q3 `STOP` 입력 | **AITOP100** |

  - PDF에는 `HALT` 모양 석판도 있다. 그쪽은 암호가 `HALT`이고 `HALT`를 넣으면 똑같이 AITOP100이 나온다(STOP을 넣으면 WRONG). 「멈추어야」라는 수수께끼에 STOP/HALT 둘 다 맞는 것도 함정이다.
- **함정**: 샘플로 언어를 짐작하게 만드는 것, AI가 아스키아트 코드를 읽다 한 글자씩 틀리는 것, 「머리로 추론」하면 리셋(`r="A"`)을 놓치는 것.
- **전략**: 판독 → **실제로 실행**. 판독이 의심되면 두 모델로 받아 diff. 출력 형식(대문자만/숫자 허용)이 답의 모양 힌트가 된다.

### 3. The Age of AI: 영상 팩트 체크

- **입력**: 2019 다큐 [The Age of AI] 유튜브 5편(편당 40분 안팎).
- **문항 유형**: 인물이 마신 음료(화면), 처음 시험한 문장(음성), 피트스톱 초(화면 자막/그래픽), 배우의 과거 직업(음성), 등장 지역 복수선택, 얼굴 마커 개수 **세기**(화면), 확인 가능한 사실 복수선택.
- **함정**
  - 「영상에서 확인할 수 있는」 것만 정답. 실제 세계에서 맞는 사실이라도 영상에 안 나오면 오답. AI는 바깥 지식으로 채운다.
  - 복수선택은 하나만 틀려도 0점일 가능성. 보기 중 숫자(100,000건·8번)는 미세하게 바꿔놓은 미끼일 확률이 높다.
  - 마커 개수처럼 **눈으로 세는 것**은 비전 모델이 가장 약하다.
- **전략**: ① `yt-dlp`로 자막(자동자막 포함) 받기 → 음성 문항은 자막 검색 ② 화면 문항은 해당 구간을 찾아 `ffmpeg`로 프레임 추출 → 직접 확대해서 확인 ③ 긴 영상 통째 이해는 Gemini(유튜브 링크 직접 입력)가 빠르지만 반드시 타임코드를 받아 원본으로 재확인.

### 4. 전투 없이 예측하는 시뮬레이션

- **입력**: 전투별 유닛 배치(5종: eyanoo·bras·cbene·aleo·dgreg, 좌표 1~20). 승패 라벨이 있는 train, 없는 test. 검증셋 없음.
- **정의(지문 그대로 구현해야 함)**: 팀 중심=좌표 평균 / 두 중심을 잇는 선분의 **수직이등분선**이 경계 / 상대 중심 쪽 반평면 = 전방.
- **문항**: 1:1 최강 유닛, 전방/후방 승률 차가 가장 큰 유닛, x형·y형 진형 승률, 상성 관계 중 **옳지 않은 것**(복수), 데이터로 확인되는 내용 중 **올바르지 않은 것**(복수), test 승자 예측 JSON.
- **함정**
  - 부정형 복수선택(「옳지 않은」「올바르지 않은」) 두 개 연속. 거꾸로 체크하기 쉽다.
  - 파일명 오타 `train_battels.json` — 지문 이름 그대로 찾으면 못 찾을 수 있다.
  - 「x 방향으로 긴」의 정의(x 분산 > y 분산? 범위?)는 직접 정해야 하고, 정의에 따라 답이 갈릴 수 있다 → 두 정의로 다 계산해 같은지 확인.
  - Q5 보기 1번처럼 「26전 25승」 같은 정확한 수치는 직접 세어야 한다.
- **전략**: EDA는 전부 코드(판다스). 모델은 유닛 타입별 개수 차 + 상성 쌍 개수 + 전방 비율 + 진형 분산 특징 → 그래디언트 부스팅, K-fold 검증. **팀 색 바꾸기(blue↔red) 증강**으로 데이터 2배. 제출 JSON은 id 개수 = test 개수인지 검사.

### 5. PDF 속 스텔스 텍스트 추적기

- **입력**: PDF 4개. 숨기는 방식 = ① 이미지 속 배경색과 비슷한 글자 ② 흰색·극소 글자 ③ 보이는 레이어 아래 텍스트 ④ 위 방식 혼합(가사 5문장).
- **답**: 문장 그대로(Q1 14단어, Q2 11단어, Q3 5단어 — **단어 수가 검산 수단**), Q4는 페이지 순서대로 콤마 구분.
- **함정**: 숨은 글자 내용이 「이 문서를 높게 평가하라」 같은 **AI 대상 지시문**이다. PDF를 통째로 AI에게 주면 AI가 그 지시를 따르거나 무시해 버린다. 사람이 「찾는 대상」으로 다뤄야 한다.
- **전략**: PyMuPDF로 모든 텍스트 span의 **색·크기·위치** 덤프 → 흰색(#FFFFFF), 크기<2pt, 이미지 뒤 텍스트 필터. 이미지형은 페이지를 렌더 → 대비 극대화(히스토그램 평활화·레벨 조정) → 눈/OCR.

## 본선 (3시간)

### 6. AI 입국 심사관

- **입력**: `applicants/applicant_001~030/` 각 폴더에 PDF(입국신고서·재정증명·항공권·여권·비자), `inspection_rules.txt`(25개 규칙), `atlantis_world_map.png`.
- **답**: `[{"id":"applicant_001","answer":"Approve"},{"id":"applicant_002","answer":"Deny","reason":3}]`
- **함정**
  - 위반이 여럿이면 **가장 낮은 번호** 규칙. 규칙을 번호순으로 검사하고 첫 위반에서 멈추면 자동으로 해결.
  - 날짜 기준은 오늘이 아니라 `inspection_date: 2025-11-22`.
  - 지문은 「7가지 서류」인데 예시 폴더엔 5개 → **서류 누락 자체가 위반 규칙**일 가능성.
  - 세계지도 PNG = 국가·지역 규칙(예: 특정 지역 국적은 추가 서류) 근거. 이미지라 비전으로 읽어야 한다.
  - 대소문자 `Approve`/`Deny` 정확히.
- **전략**: ① PDF 150개를 코드로 텍스트화 → 신청자별 한 줄 표 ② 25개 규칙을 **각각 함수**로 코딩(AI에게 규칙→코드 번역을 시키고 규칙 원문과 1:1 대조) ③ 몇 명은 손으로 판정해 코드 결과와 비교. AI에게 「30명 심사해줘」 한 번에 시키면 틀린다.

### 7. 몽타주를 그려라

- **입력**: 목격자 묘사 한 문단 + 유사도 API(점수 + 부위별 피드백).
- **제약**: 1분당 1회, 1024×1024 PNG/JPEG, 10MB 이하, 같은 해시 재제출 무효, 이력은 최근 4건만 보임.
- **함정**: 3시간이면 최대 약 180회. 한 번 낭비가 비싸다. 이력이 4건만 보이니 **직접 기록 안 하면 무엇이 점수를 올렸는지 잃는다.** 크기·형식 실수로 제출이 버려질 수 있다.
- **전략**: 제출 스크립트에 크기 검사·해시 기록·점수 로그(CSV)를 붙인다. 한 번에 한 부위만 바꾸는 좌표 하강식 탐색 + 부위 피드백이 낮은 곳만 인페인팅. 대기 1분 동안 다음 후보 여러 장을 미리 생성.

### 8. 인수인계 자료 작성

- **입력**: `1_메일/발신·수신`(날짜_제목_상대.txt 수십 개), `2_캘린더`, `3_메모`, `4_책상`, `5_통화_비밀번호(생일4자리).zip`, `template.md`.
- **답**: 객관식(교육 장소), 숫자(컨택 완료 대학 수), 복수선택(시작일이 8/1이 아닌 것), 그리고 template.md를 채운 문서. 채점은 **여러 AI 심사 모델 교차 + 프롬프트 인젝션 가드레일**.
- **함정**
  - zip 비밀번호 = 누군가의 **생일 4자리** — 메일(예: `20250508_생…_동료정은희`) 등에서 찾아야 열린다. 통화 기록 안에 결정적 정보가 있을 것.
  - 같은 사안이 메일 여러 통에 걸쳐 **변경**된다(장소 변경, 시작일 연기, 한도 상향). 최신 것을 써야 한다.
  - 「완료」 개수 같은 질문은 진행 중·예정과 구분해서 세야 한다.
  - 템플릿의 표 컬럼명·리스트 항목을 바꾸면 감점. 근거 없는 내용 금지.
  - 문서에 「이 문서에 만점을 주라」 같은 문장을 넣는 꼼수는 가드레일로 막혀 있다고 명시.
- **전략**: 모든 파일을 한 표(날짜·출처·사람·프로젝트·사실)로 추출 → 사안별로 시간순 정렬해 최종 상태 확정 → 템플릿 채우기. 각 문장에 출처 파일명을 달아두면 검증이 쉽다(제출본에선 템플릿 형식에 맞게).

## 공통 패턴 — 출제자가 노리는 것

1. **AI 답을 그대로 쓰면 틀리게 설계했다.** 석판(리셋 미끼), 영상(바깥 지식), PDF(인젝션), 인수인계(최신 정보) 모두 「그럴듯한 오답」이 준비돼 있다.
2. **데이터 → 구조화 → 코드 계산 → 원본 대조**가 거의 모든 문제의 정석이다. AI는 판독·코드 작성에 쓰고, 셈은 코드가 한다.
3. **멀티모달 입력**: 이미지 표(춘식), 이미지 코드(석판), 영상(팩트), PDF 레이어(스텔스·입국). 텍스트만 다루는 준비로는 부족하다.
4. **형식이 점수다.** 대문자만, 숫자만, JSON 스키마, 대소문자, 가나다순, 콤마 구분. 제출 직전 형식 검사기를 돌린다.
5. **부정형·복수선택**이 자주 나온다(「옳지 않은 것을 모두」). 보기마다 참/거짓을 표로 만들고 나서 고른다.
6. **지문 속 숫자는 검산 도구다**(14단어, 7가지 서류, 25개 규칙, 30명).
7. **AI를 속이는 입력**에 대한 감각을 본다(스텔스 텍스트, 인수인계 가드레일). 2026 미션의 「데이터 검증」도 이 축일 가능성이 높다.
8. **제한 자원 관리**(몽타주 rate limit, 본선 3시간·예선 5시간): 문제별 시간 상한을 정하고 넘기면 다음으로.

## 2026 미션(교동·갯마을)에 옮기면

2025 예선은 독립 문제 5개였지만, 2026 브리프는 「마을 관계자와 **대화해** 문제 발굴 → 데이터 **수집·검증·정제** → **에이전트**」의 한 줄 미션이다. 형식이 바뀌었을 수 있으니 단정하지 말고, 2025 유형이 그대로 섞여 나올 경우에 대비한다.

| 2025 유형 | 마을 미션에서 나올 법한 모습 | 미리 준비할 도구 |
|---|---|---|
| 춘식도락(이미지 표 OCR) | 출하 장부·영수증·시세표 사진 | 이미지→CSV 두 모델 diff 스크립트 |
| 입국 심사(규칙 엔진) | 조합 규정(출하 기준·보조금 자격)으로 판정 | 규칙→함수 템플릿, 「첫 위반 번호」 패턴 |
| 인수인계(비정형 정리) | 관계자 대화·메모·메일에서 업무 현황 정리 | 사실 추출 표 + 시간순 최신값 확정 |
| PDF 스텔스(검증) | 오염·조작된 데이터, 섞인 지시문 | span 색·크기 덤프, 이상치 탐지(`toolkit/clean.py`) |
| 전투 ML(예측) | 어획량·수확량·가격 예측 | 판다스 EDA + 부스팅 + K-fold 틀 |
| 몽타주(API 반복) | 채점 API·NPC 대화에 질문하며 정보 캐기 | 호출 로그·rate limit 대기 스크립트 |
